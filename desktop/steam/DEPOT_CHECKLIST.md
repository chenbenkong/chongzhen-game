# Steamworks 后台上架检查清单

> 这份清单按**必须完成的先后顺序**排列。前面没做完，后面的步骤在后台里根本点不动。
> 所有操作都在 <https://partner.steamgames.com/> 完成。
> 勾选状态请在复制出去的工作副本上维护，本文件保持为模板。

---

## 阶段 0：前置费用与账号

- [ ] **1. 注册 Steamworks 合作伙伴账号**
      - 需要：真实姓名、地址、税号（中国区个人开发者需填身份证信息）
      - 需要：能收验证邮件的邮箱 + 手机号（用于两步验证）
      - 进入 <https://partner.steamgames.com/steamdirect> 开始注册

- [ ] **2. 支付 $100 USD 的 Steam Direct 费用（每款游戏一次）**
      - 这是**上架费**，不是分成。游戏累计营收达到 $1000 后这笔钱会退还。
      - 支付后会要求填写**税务信息**（W-8BEN 表，中国个人开发者填这个），否则无法收款。
      - 同一账号再上第二款游戏要再付 $100。

- [ ] **3. 等待账号审核通过**
      - 通常 1–5 个工作日。期间无法创建 App。

## 阶段 1：创建 App 与 Depot

- [ ] **4. 创建新 App**（后台 → 「创建新的应用」）
      - 填游戏名：`崇祯 · 宦海浮沉`
      - 创建后系统会分配一个 **AppID（一串数字）** —— 记下来。
      - ⚠️ AppID 一旦创建**不可更改**。

- [ ] **5. 把真实 AppID 写进项目**
      - `desktop/steam/steam_appid.txt` 里的 `480` 改成你的真实 AppID
      - `desktop/steam/steamconfig.json` 里的 `appId` 改成同一个数字
      - `desktop/steam/steamconfig.example.json` 保持 480 不变（它只是模板）

- [ ] **6. 创建 1 个 Depot**（后台 → 该 App → 「SteamPipe」→「Depots」）
      - 点「添加新的 Depot」，系统分配一个 **DepotID**（通常紧邻 AppID）
      - 把 DepotID 填进 `desktop/steam/steamconfig.json` 的 `depotId`
      - 本项目只需要 **1 个 depot**（不需要分语言 depot）

- [ ] **7. 设置 Depot 的安装目录名（InstallDir）**
      - Depot 属性里的「安装目录」字段，例如填 `Chongzhen`
      - ⚠️ **这个字段以后改名会导致老玩家游戏"丢失"**（Steam 会重新下一份），
        所以第一次就要定好，不要随便改。
      - 建议用纯英文，避免某些系统上的编码问题。

- [ ] **8. 把 Depot 关联到 App**
      - 在 App 的 Depot 列表里把刚创建的 depot 勾选进来
      - 没关联的话上传会失败（`upload.mjs` 会以非零码退出）

- [ ] **9. 配置启动选项（Launch Options）**（后台 → 该 App → 「安装」→「通用安装」）
      - 添加一条 Windows 启动项，可执行文件填：
        `崇祯 · 宦海浮沉.exe`（相对于 InstallDir 的路径）
      - 操作系统选 Windows
      - ⚠️ 如果 exe 名字里有中文/空格，这里必须**完全一致**（含大小写）
      - 若将来支持 Linux/macOS，再各加一条

## 阶段 2：成就配置（本项目最需要注意的一步）

- [ ] **10. 在后台逐个创建成就 API Name**

      ⚠️ **硬性限制：单个 App 最多 100 个成就。**
      本项目 `src/types/achievement.ts` 里实测有 **105** 个成就，
      **不可能全部上线**，必须先裁剪或合并（详见 `desktop/steam.cjs` 顶部注释里的三个方案）。

      每个成就在后台要填 4 个字段：
      | 字段 | 说明 |
      | --- | --- |
      | **API Name** | 必须与 `desktop/steam.cjs` 里 `ACHIEVEMENTS` 的 KEY **逐字符完全一致**（大写蛇形，如 `FROM_NINTH`）。⚠️ 创建后不可修改，只能删除重建。 |
      | **显示名称** | 玩家看到的名字，填中文，例如 `从九起步`（可与映射表里的 `name` 一致） |
      | **描述** | 达成条件说明，例如 `担任从九品司狱` |
      | **图标** | 未解锁 / 已解锁两张图，后台要求 64×64 的 JPG/PNG |

      - [ ] 决定最终保留哪 100 个（或更少）
      - [ ] 把被裁掉的成就从 `desktop/steam.cjs` 的 `ACHIEVEMENTS` 里删除或注释掉，
            并同步修正 `INTERNAL_ACHIEVEMENT_COUNT` 常量
      - [ ] 逐个填完所有保留成就的 4 个字段
      - [ ] 用 `node desktop/smoke-test.cjs` 自查映射表与游戏内 id 是否一一对应

- [ ] **11. 准备成就图标素材**
      - 每个成就 2 张：未解锁（灰度）、已解锁（彩色）
      - 建议统一风格，尺寸严格 64×64

## 阶段 3：Steam Cloud（可选，但强烈建议先开）

- [ ] **12. 启用 Steam Cloud**（后台 → 该 App → 「Steam Cloud」）
      - 打开「启用 Steam 云同步」
      - 设置**每个用户的字节配额**（Byte Quota）。建议先给 `10485760`（10 MB）——
        本项目存档是 JSON 文本，10 MB 绰绰有余
      - 如需要，再设置「每个文件的最大字节数」

      ⚠️ **重要：开了后台开关 ≠ 游戏就会用云存档。**
      游戏本体的存档目前写在 Electron profile 的 `localStorage` 里（键前缀 `chongzhen_`），
      **完全不在 Steam Cloud 的覆盖范围内**。
      要真正用上云存档，必须把游戏改成通过
      `window.chongzhenDesktop.steam.setCloudFile()` / `saveToDisk()` 读写存档 ——
      这是**尚未开始的后续任务**，详见 `desktop/README.md` 的「尚未完成的部分」。

- [ ] **13.（可选）配置 Auto-Cloud**
      - 本项目用的是显式 API 调用路径，不走 Auto-Cloud，此步可跳过

## 阶段 4：商店页面

- [ ] **14. 填写商店页面必备内容**（后台 → 该 App → 「商店页面」）
      - [ ] 游戏简介（短描述 ≤ 300 字符 + 详细描述）
      - [ ] **至少 5 张截图**（1280×720 或 1920×1080，无边框、无营销文案）
      - [ ] **封面图**：Header Capsule 460×215（必需）
      - [ ] 其他尺寸：Small Capsule 231×87、Main Capsule 1232×706、Hero 3840×1240 等
      - [ ] **宣传片**（可选但强烈建议，Steam 算法会加权）
      - [ ] 系统需求（最低 / 推荐，Windows 要写清 Win10+）
      - [ ] 支持的语言列表
      - [ ] 开发商 / 发行商名称
      - [ ] 标签（Tags）：历史、模拟、文字冒险、选择取向、单人
      - [ ] 是否支持成就 / Steam Cloud（要与阶段 2、3 的实际配置一致）

- [ ] **15. 填写「商店页面可见性」**
      - [ ] 设置**发行日期**（可先设"即将推出"）
      - [ ] ⚠️ 商店页面发布后**需要等 2 周**才能正式开卖（Steam 的冷却期规则）
      - [ ] 页面发布后建议立刻开始积累愿望单

## 阶段 5：内容与合规问卷

- [ ] **16. 完成内容调查问卷（Content Survey）**
      - 后台 → 该 App → 「年龄与内容」/「内容调查」
      - 必须如实回答：暴力、血腥、色情、成人内容、赌博等
      - ⚠️ 本项目是历史向文字模拟，涉及明末战乱、死亡、贪腐、妓院等情节，
        **要如实勾选**。隐瞒被查到会直接下架。

- [ ] **17. 配置年龄门（Age Gate）**
      - 若问卷结果显示需要年龄限制，后台会要求设置年龄门
      - 按问卷结论如实设置（本项目预计为"仅成人内容相关描述"，可能不需要硬性年龄门，
        但**必须由问卷结果决定**，不要自己拍脑袋）

- [ ] **18. 生成并检查 Steam 的年龄分级问卷**
      - 部分区域（如德国、韩国、澳洲）需要额外分级，后台会提示

## 阶段 6：提交审核与上线

- [ ] **19. 上传第一个 build**
      - 用 `node desktop/steam/upload.mjs` 上传（详见 `desktop/steam/README.md`）
      - 在后台「Builds」页面确认 build 成功入库（`upload.mjs` 成功不代表后台一定入库）
      - 先设到 `beta` 分支自测，确认无误再「Set Build Live」到 `default`

- [ ] **20. 自测 checklist（强烈建议在上线前跑一遍）**
      - [ ] 通过 Steam 库启动游戏，能正常进入标题页
      - [ ] 存档 / 读档正常，退出重进存档还在
      - [ ] 解锁一个成就，Steam 弹出成就提示（需要 Steam 客户端覆盖层正常工作）
      - [ ] F11 全屏切换正常
      - [ ] 断网启动，游戏不崩（确认 Steam 失败的降级路径有效）
      - [ ] 卸载后重装，存档不丢（存档在 `%APPDATA%` 下，正常情况下不会被卸载删除）

- [ ] **21. 点击「审核」按钮提交商店页面审核**
      - 审核通常 1–5 个工作日
      - 被驳回会收到具体原因邮件，修好后可重新提交

- [ ] **22. 满足发行条件后手动点击「发布」**
      - 条件：商店页面已通过审核 **且** 已过 2 周冷却期 **且** 至少有一个 build 在 `default` 分支
      - ⚠️ Steam **不会**自动发布，必须手动点

## 阶段 7：发行后

- [ ] **23. 配置 Steam Cloud 的实际配额观察**
      - 上线后看后台的 Cloud 用量统计，必要时调整配额

- [ ] **24. 准备后续更新的上传流程**

## 常见踩坑提醒

| 坑 | 后果 | 预防 |
| --- | --- | --- |
| 带着 `steam_appid.txt` 里的 `480` 发行 | 成就写到 Spacewar 上，云存档与他人的测试数据混在一起 | 发行前全局搜一遍 `480` |
| depot 里打了 `steam_appid.txt` | 可能覆盖 Steam 注入的 AppID | `upload.mjs` 已加 `FileExclusion`，勿删 |
| 成就 API Name 打错一个字母 | 该成就永远解锁不了，且后台改不了 API Name | 用 `node desktop/smoke-test.cjs` 自检 |
| 成就要建 105 个 | 后台直接拒绝（上限 100） | 先裁剪/合并，见阶段 2 |
| InstallDir 上线后又改 | 老玩家的游戏被"重新下载"一份 | 第一次就定好 |
| 以为开了 Steam Cloud 开关就有云存档 | 玩家换机器存档丢失 | 必须先完成存档迁移（后续任务） |
| 忘了填税务信息 | 赚了钱也收不到 | 阶段 0 就填完 W-8BEN |
| 上传成功但没切 Live | 玩家下载到的还是旧版本 | 后台手动 Set Build Live |
